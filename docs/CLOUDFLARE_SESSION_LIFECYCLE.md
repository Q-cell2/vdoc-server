# Cloudflare 会话存储与生命周期

本服务保存的是语音会话快照，不是用户的文档库或登录账户。文档/账户使用 Neon
时仍可保留本服务：Web Worker 先验证用户对文档的所有权，再调用语音服务。
不同用户的同名文档应映射为不同的 transport document ID，避免进入同一个房间。

## 持久化和并发

- 保留现有 `DocumentVoiceRoom` 类、`VOICE_ROOMS` 绑定和 `v1` SQLite migration。
  不需要删除/重建 Durable Objects，也不需要增加 Postgres 连接。
- `v2` migration 增加按 principal 隔离的 `PrincipalQuotaRoom` 和 `PRINCIPAL_QUOTAS`
  绑定，负责跨文档配额。结束提交释放名额；租约和频率窗口可独立通过 alarm 清理，
  见 [跨文档配额](PRINCIPAL_QUOTAS.md)。
- 快照内容沿用原有 `voice-session:` 键格式；包括文档、调用者、会话状态、授权截止
  时间、使用量和待确认操作。构造函数为旧快照补建缺失的 alarm。
- 存储事务原子提交快照和 alarm。写入 alarm 失败时不能留下没有唤醒安排的快照。
- 一个对象对应一篇文档。所有应用命令通过同一串行队列执行，包括 HTTP、实时工具
  回调和超时处理。队列覆盖鉴权/签名等外部 await；单靠 DO 的存储输入门不能防止
  这些 await 之间出现读改写竞争。某条命令失败不会堵住后续命令。
- 实时 WebSocket 和模型连接仍在运行时内存中。存储恢复不等于音频连接恢复；客户端
  需重新连接并提供有效授权。稳定的签名密钥和调用方配置是跨重启验证授权的前提。

## 过期与清理

Alarm 重新读取当前快照并检查实际截止时间，避免旧 alarm 结束刚续期的授权。
未连接授权在连接期限后结束为 `expired`；活动会话达到最大时长时结束为
`limit-duration`，并请求关闭现有实时连接。重复 alarm 不重复产生结束事件。

已结束会话保留七天，然后删除。扫描/删除按每页 128 个键处理；即使无人再访问，
alarm 仍负责清理并安排下一次唤醒。保留期内可查询会话状态，七天后返回不存在。
这不是永久审计日志或计费账本；如需长期审计，应另行设计可靠事件归档。

## 验证

`npm run check` 包括类型检查、架构检查、应用/适配器/Node 测试，以及本地 workerd：

- 多个同时授权在 reject 策略下只允许一个；并发回合计数不丢失。
- 关闭与迟到回调并发时不会复活会话；旧 alarm 不会结束已续期授权。
- 使用真实 SQLite 持久化目录停止并重启 workerd，确认会话快照恢复。
- 不调用会话查询 API，直接观察 alarm 完成过期/结束/七天保留清理。
- 批量清理 300 个快照，保留活动会话及保留期内的数据。

运行时测试使用测试专用 bundle 增加存储观察入口，不会进入生产 Worker。
测试需要本地监听端口，不连接真实语音提供商。上线后仍需用实际密钥验证一次
创建、连接、工具调用、续期、结束的完整语音流程。
